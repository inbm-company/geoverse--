# 관리 서버

## 1.1 개요

### 기능 설명

GeoVerse 서버 중 **관리 서버**는 모니터링 시스템의 설정과 기준 정보를 다루는 역할을 한다. 웹 관리 화면에서 이루어지는 등록·수정·삭제가 모두 이 서버를 거친다.

- 사용자 로그인과 계정 관리를 담당한다.
- 현장을 등록하고, 현장 안의 계층 구조와 장비·센서를 구성한다.
- 대시보드에 무엇을 어떤 순서로 보여 줄지(센서 그룹, 위젯, CCTV, 조감도) 설정한다.
- 알람 기준이 되는 임계값과 연락처를 관리하고, 발생한 알람 이력을 조회한다.

센서 측정값을 직접 수집하거나 조회하지는 않는다. 데이터 수집은 **수집 서버**가, 화면용 데이터 조회는 **센서 조회 서버**가 담당한다.

### 기본 정보

| 항목 | 내용 |
| --- | --- |
| 기본 포트 | 3001 |
| 사용 대상 | 웹 관리 화면, 로그인 화면 |
| 기준 정보 보관 | PostgreSQL |

서버가 살아 있는지 확인하는 상태 확인 기능(`GET /health`)을 제공하며, 등록된 조감도 이미지는 `/images` 경로로 내려 준다.

### 예외 처리

- 데이터베이스 연결에 실패하면 서버는 계속 실행되지만 기준 정보 관련 기능을 사용할 수 없다.
- 별도의 권한 검사 없이 내부망에서 사용하는 것을 전제로 한다.

## 1.2 연동 대상

### 기능 설명

관리 서버는 아래 대상과 연동한다.

| 연동 대상 | 용도 |
| --- | --- |
| PostgreSQL | 현장·계층·장비·센서·사용자·임계값 등 기준 정보 보관 |
| Redis | 로그인 토큰 보관, 백업 후 데이터 정리 |
| InfluxDB | 알람 이력 조회 |
| 수집 서버 | 임계값 변경 시 알람 기준 갱신 요청 |
| 문자 발송 서비스 | 문자 발송 연동 확인 |
| 외부 백업 서버 | 측정 데이터 백업 전송 |

### 예외 처리

- 수집 서버가 중단된 상태에서 임계값을 저장해도 관리 서버 저장은 정상 처리된다. 다만 수집 서버가 재시작될 때까지 새 기준이 적용되지 않을 수 있다.

## 1.3 로그인

### 기능 설명

사용자 계정으로 로그인하여 **접속 토큰**을 발급받는다. 발급된 토큰은 만료되기 전에 갱신할 수 있고, 로그아웃하면 더 이상 사용할 수 없게 된다.

### 요청 형식

| 기능 | 요청 |
| --- | --- |
| 로그인 | `POST /api/auth/login/v2` |
| 토큰 갱신 | `POST /api/auth/refresh` |
| 로그아웃 | `POST /api/auth/logout` |
| 토큰 확인 | `GET /api/auth/verify` |
| 내 정보 조회 | `GET /api/auth/me` |

로그인 요청에는 아이디(`username`)와 비밀번호(`password`)가 필요하다.

### 처리 절차

1. 아이디로 계정을 조회한다.
2. 계정 상태가 사용 가능한지 확인한다.
3. 비밀번호가 일치하는지 확인한다.
4. 접속 토큰과 갱신 토큰을 발급한다.
5. 마지막 접속 시각을 기록한다.

### 응답 규칙

| 항목 | 내용 |
| --- | --- |
| user | 아이디, 이름, 역할, 소속 현장, 계정 상태 |
| accessToken | 화면 요청에 사용하는 접속 토큰 |
| refreshToken | 접속 토큰을 다시 발급받을 때 사용 |

### 예외 처리

- 아이디나 비밀번호가 틀리면 어느 쪽이 틀렸는지 구분하지 않고 인증 실패로 응답한다.
- 계정이 비활성화 또는 잠긴 상태면 사유를 안내한다.
- 갱신 토큰이 만료되었으면 다시 로그인해야 한다.
- 로그아웃한 토큰은 만료 시각까지 사용할 수 없도록 차단된다.

## 1.4 사용자 관리

### 기능 설명

시스템을 사용할 **계정을 등록하고 관리**한다. 계정마다 역할과 소속 현장을 지정할 수 있다.

### 요청 형식

```text
GET    /api/users
GET    /api/users/{아이디}
POST   /api/users
PATCH  /api/users/{아이디}
DELETE /api/users/{아이디}
```

목록 조회 시 소속 현장(`siteCode`), 역할(`role`), 상태(`status`)로 걸러 볼 수 있다.

### 표시 규칙

| 항목 | 설명 |
| --- | --- |
| 아이디 | 로그인에 사용. 등록 시 필수 |
| 이름 | 화면에 표시되는 사용자 이름. 등록 시 필수 |
| 역할 | 사용자 구분. 등록 시 필수 |
| 소속 현장 | 담당 현장 코드 |
| 연락처·이메일 | 알람 통지 등에 활용 |
| 상태 | 사용 가능 여부 |
| 마지막 접속 | 최근 로그인 시각 |

### 예외 처리

- 아이디, 비밀번호, 이름, 역할이 빠지면 등록할 수 없다.
- 없는 아이디를 수정·삭제하려 하면 대상을 찾을 수 없다고 응답한다.

## 1.5 현장 관리

### 기능 설명

모니터링 대상이 되는 **현장을 등록하고 현장별 설정을 관리**한다. 현장은 시스템의 최상위 단위이며, 계층 구조·장비·화면 구성이 모두 현장에 속한다.

현장에는 다음 정보가 함께 저장된다.

- 현장 이름과 현장 코드
- 현장 개요 정보
- 조감도 이미지 경로
- 조감도 위의 마커 위치
- 날씨 표시에 사용할 좌표
- 알람 연락처(1차·2차·3차)

### 요청 형식

| 기능 | 요청 |
| --- | --- |
| 현장 목록 | `GET /api/projects` |
| 현장 조회 | `GET /api/projects/{번호}` 또는 `GET /api/projects/site/{현장코드}` |
| 현장 등록 | `POST /api/projects` |
| 현장 수정 | `PUT /api/projects/{번호}` |
| 현장 삭제 | `DELETE /api/projects/{번호}` |
| 조감도 마커 변경 | `PATCH /api/projects/{번호}/markers` |
| 센서·위젯 마커 변경 | `PATCH /api/projects/{번호}/sensor-markers` |
| 알람 연락처 변경 | `PATCH /api/projects/{번호}/alarm-contacts` |
| 조감도 이미지 경로 변경 | `PATCH /api/projects/{번호}/blueprint-image` |
| 현장 구성 요약 | `GET /api/projects/{번호}/statistics` |
| 현장의 센서 그룹 목록 | `GET /api/projects/{번호}/sensor-groups` |

현장 번호 대신 현장 코드로 조회할 수 있는 기능도 함께 제공한다.

### 표시 규칙

마커와 연락처는 **자주 바뀌는 항목**이라 현장 전체를 수정하지 않고 해당 부분만 변경할 수 있도록 별도 기능으로 분리되어 있다.

알람 연락처는 단계별로 나뉘며, 세 단계 모두 목록 형태로 관리한다.

| 단계 | 용도 |
| --- | --- |
| 1차 | 1단계 임계값 초과 시 통지 대상 |
| 2차 | 2단계 임계값 초과 시 통지 대상 |
| 3차 | 3단계 임계값 초과 시 통지 대상 |

현장 구성 요약에서는 계층 수, 센서 그룹 수, 센서 수를 확인할 수 있다.

### 예외 처리

- 현장 이름이 없으면 등록할 수 없다.
- 좌표는 위도와 경도를 함께 입력해야 한다. 둘 다 비우면 날씨 표시를 사용하지 않는 것으로 처리한다.
- **현장을 삭제하면 그 현장에 속한 계층·장비·센서 그룹·위젯이 함께 삭제된다.** 되돌릴 수 없으므로 삭제 전 확인이 필요하다.

## 1.6 현장 계층 구성

### 기능 설명

현장 안을 **구역·동·층 같은 계층으로 나누어 관리**한다. 계층은 여러 단계로 중첩할 수 있고, 관리 화면의 트리로 표시된다. 계층 안에는 다시 폴더를 만들어 장비 목록을 묶을 수 있다.

### 요청 형식

계층(노드) 관련 기능이다.

| 기능 | 요청 |
| --- | --- |
| 최상위 계층 목록 | `GET /api/nodes/top-level` |
| 계층 조회 | `GET /api/nodes/{번호}` |
| 바로 아래 계층 목록 | `GET /api/nodes/{번호}/children` |
| 하위 전체 계층 | `GET /api/nodes/{번호}/subtree` |
| 상위 계층 경로 | `GET /api/nodes/{번호}/ancestors` |
| 현장 전체 트리 | `GET /api/nodes/tree/{현장번호}` |
| 계층 등록 | `POST /api/nodes` |
| 계층 수정·이동 | `PUT /api/nodes/{번호}` |
| 계층 삭제 | `DELETE /api/nodes/{번호}` |

폴더 관련 기능이다.

| 기능 | 요청 |
| --- | --- |
| 폴더 목록 | `GET /api/folders` |
| 폴더 조회 | `GET /api/folders/{번호}` |
| 폴더 등록·수정·삭제 | `POST` / `PUT` / `DELETE /api/folders` |

폴더 목록은 계층 번호(`nodeId`) 또는 현장 코드(`siteCode`) 중 **하나만** 지정해서 조회한다.

### 처리 절차

계층을 등록할 때는 상위 계층을 지정한다. 상위를 지정하지 않으면 최상위 계층으로 만들어지며, 표시 순서는 같은 위치의 기존 항목 다음으로 자동 지정된다.

계층을 다른 상위로 옮기면 **그 아래 있던 모든 하위 계층의 위치도 함께 옮겨진다.**

### 예외 처리

- 계층 이름이 없으면 등록할 수 없다.
- 상위 계층이 존재하지 않으면 등록할 수 없다.
- 다른 현장으로는 계층을 옮길 수 없다.
- 하위 계층이나 센서 그룹이 있는 계층은 삭제되지 않는다. 함께 삭제하려면 별도 옵션을 지정해야 한다.
- 폴더 조회 시 계층 번호와 현장 코드를 동시에 지정하면 요청이 거부된다.

## 1.7 장비 및 센서 등록

### 기능 설명

현장 계층 아래에 **실제 설치된 장비를 등록**하고, 장비가 가진 측정 채널을 설정한다. 장비와 센서의 종류는 따로 목록으로 관리하여 등록할 때 선택할 수 있게 한다.

### 요청 형식

장비 관련 기능이다.

| 기능 | 요청 |
| --- | --- |
| 계층별 장비 목록 | `GET /api/devices` |
| 전체 장비 목록 | `GET /api/devices/all` |
| 하위 계층 포함 장비 목록 | `GET /api/devices/subtree` |
| 장비 조회 | `GET /api/devices/{번호}` |
| 장비 등록 | `POST /api/devices` |
| 장비 수정 | `PUT /api/devices/{번호}` |
| 채널 전체 변경 | `PUT /api/devices/{번호}/channels` |
| 장비 삭제 | `DELETE /api/devices/{번호}` |

종류 관리 기능이다.

| 기능 | 요청 |
| --- | --- |
| 장비 종류 | `GET` / `POST` / `PUT` / `DELETE /api/device-types` |
| 센서 종류 | `GET` / `POST` / `PUT` / `DELETE /api/sensor-types` |

### 표시 규칙

장비에는 다음 정보를 저장한다.

| 항목 | 설명 |
| --- | --- |
| 소속 계층 | 장비가 설치된 위치. 등록 시 필수 |
| 소속 폴더 | 목록에서 묶어 보여 줄 폴더. 지정하지 않으면 계층에 직접 소속 |
| 장비 이름 | 화면에 표시되는 이름. 등록 시 필수 |
| 장비 식별자 | 수집 데이터와 연결하는 실제 장비 ID |
| 장비 종류·모델 | 종류 목록에서 선택 |
| 통신 방식 | 데이터 수집 경로 구분 |
| 채널 | 장비가 측정하는 항목 목록 |
| 센서 수 | 장비에 연결된 센서 개수 |
| 사용 여부 | 화면 표시 대상 여부 |

장비 목록은 특정 계층의 직속 장비만 볼 수도 있고, 하위 계층까지 모두 포함해 볼 수도 있다. 하위 포함 조회는 계층 번호 또는 현장 코드로 지정한다.

### 예외 처리

- 소속 계층과 장비 이름이 없으면 등록할 수 없다.
- 존재하지 않는 계층이나 폴더를 지정하면 등록할 수 없다.
- 폴더는 장비와 같은 계층에 속한 것만 지정할 수 있다.
- 채널 이름은 비워 둘 수 없고, 한 장비 안에서 중복될 수 없다.
- 채널 변경은 기존 채널을 **전체 교체**하는 방식이다. 일부만 바꾸려면 기존 목록을 포함해서 보내야 한다.
- 장비의 소속 계층을 옮기면서 기존 폴더가 새 계층에 없으면 폴더 지정이 해제된다.

## 1.8 화면 구성

### 기능 설명

대시보드에 **무엇을 어떤 순서로 보여 줄지 설정**한다. 현장 유형에 따라 센서 그룹 또는 위젯을 사용하며, CCTV 목록과 조감도 이미지도 여기서 등록한다.

### 요청 형식

센서 그룹 관련 기능이다.

| 기능 | 요청 |
| --- | --- |
| 그룹 목록 | `GET /api/sensor-groups` |
| 그룹 조회 | `GET /api/sensor-groups/{번호}` |
| 그룹의 센서 목록 | `GET /api/sensor-groups/{번호}/sensors` |
| 현장별 그룹 목록 | `GET /api/sensor-groups/site/{현장코드}` |
| 계층별 그룹 목록 | `GET /api/sensor-groups/node/{계층번호}` |
| 그룹 등록·수정·삭제 | `POST` / `PUT` / `DELETE /api/sensor-groups` |
| 표시 여부 전환 | `PATCH /api/sensor-groups/{번호}/toggle-visibility` |
| 순서 일괄 변경 | `PATCH /api/sensor-groups/reorder` |

위젯 관련 기능이다.

| 기능 | 요청 |
| --- | --- |
| 위젯 목록 | `GET /api/sensor-widgets` |
| 장비·채널로 위젯 찾기 | `GET /api/sensor-widgets/by-device-channel` |
| 위젯 조회 | `GET /api/sensor-widgets/{번호}` |
| 위젯 등록·수정·삭제 | `POST` / `PUT` / `DELETE /api/sensor-widgets` |
| 표시 여부 전환 | `PATCH /api/sensor-widgets/{번호}/toggle-visibility` |
| 순서 일괄 변경 | `PATCH /api/sensor-widgets/reorder` |

CCTV 및 조감도 관련 기능이다.

| 기능 | 요청 |
| --- | --- |
| CCTV 목록 | `GET /api/cctv-cameras` |
| CCTV 등록·수정·삭제 | `POST` / `PUT` / `DELETE /api/cctv-cameras` |
| CCTV 순서 변경 | `PATCH /api/cctv-cameras/reorder` |
| 조감도 이미지 업로드 | `POST /api/blueprint/upload` |

### 처리 절차

조감도 이미지 업로드는 다음 순서로 처리된다.

1. 이미지 파일과 현장 코드를 함께 전송한다.
2. 파일 형식과 크기를 확인한다.
3. 현장이 존재하는지 확인한다.
4. 현장 코드가 붙은 이름으로 파일을 저장한다.
5. 저장된 이미지 경로를 현장 정보에 반영한다.

### 표시 규칙

| 항목 | 설명 |
| --- | --- |
| 표시 여부 | 화면에 보이거나 숨긴다. 삭제하지 않고 감출 때 사용 |
| 표시 순서 | 대시보드에 나열되는 순서. 여러 항목을 한 번에 바꿀 수 있다 |
| 위젯 종류 | 위젯이 어떤 형태로 표시될지 결정 |
| 위젯 설정 | 위젯이 사용할 장비·채널과 표시 항목 |

CCTV는 현장별로 이름과 접속 주소를 등록하며, 목록 조회 시 현장 코드가 반드시 필요하다.

업로드 가능한 조감도 이미지는 **JPEG, PNG, GIF, WebP 형식이며 최대 5MB**다.

### 예외 처리

- 센서 그룹은 현장 번호 또는 현장 코드 중 하나를 지정해야 조회된다.
- 센서 그룹 등록 시 현장과 이름이 필요하며, 계층을 지정할 경우 같은 현장의 계층이어야 한다.
- 위젯 등록 시 이름과 위젯 종류가 필요하다.
- 조감도 이미지의 형식이나 크기가 맞지 않으면 업로드가 거부된다.
- 등록되지 않은 현장 코드로 조감도를 업로드하면 저장되지 않는다.

## 1.9 임계값 설정

### 기능 설명

센서 측정값이 **어느 수준을 넘으면 알람으로 볼 것인지 기준을 설정**한다. 여기서 저장한 기준을 수집 서버가 읽어 알람을 판정한다.

### 요청 형식

| 기능 | 요청 |
| --- | --- |
| 현장 임계값 조회 | `GET /api/thresholds/{현장코드}` |
| 현장 임계값 일괄 저장 | `POST /api/thresholds/{현장코드}` |
| 장비·채널 임계값 조회 | `GET /api/thresholds/device/{장비ID}/{채널}` |
| 장비 임계값 전체 삭제 | `DELETE /api/thresholds/device/{장비ID}` |

### 표시 규칙

임계값 한 건은 다음 항목으로 구성된다.

| 항목 | 설명 |
| --- | --- |
| 장비 ID · 채널 · 측정 항목 | 기준을 적용할 대상. 모두 필수 |
| 데이터 구분 | 일반 측정값 또는 주파수 분석값 |
| 양방향 여부 | 켜면 음수 방향 초과도 알람으로 판정 |
| 1·2·3단계 한계값 | 단계별 알람 기준 |
| 지속 시간 | 기준을 넘은 상태가 이 시간 이상 유지될 때 알람 발생 |
| 재알람 대기 시간 | 알람 발생 후 다시 알리기까지 기다리는 시간 |

### 처리 절차

1. 항목별로 필수 값과 형식을 확인한다.
2. 기존에 같은 대상의 기준이 있으면 덮어쓰고, 없으면 새로 만든다.
3. 수집 서버에 기준이 바뀌었음을 알려 새 기준을 적용하게 한다.

### 예외 처리

- 저장할 항목이 하나도 없으면 요청이 거부된다.
- 필수 항목이 빠지거나 숫자 형식이 아니면 어느 항목의 문제인지 함께 안내한다.
- 수집 서버에 연락이 되지 않아도 저장은 정상 처리된다.
- 삭제할 기준이 없으면 대상을 찾을 수 없다고 응답한다.

## 1.10 알람 이력

### 기능 설명

**발생한 알람 기록을 기간별로 조회**한다. 알람 발생 시각, 대상 센서와 채널, 발생 내용을 확인할 수 있다.

### 요청 형식

```text
GET /api/alarm-logs/site/{현장코드}
```

| 항목 | 필수 | 기본값 | 설명 |
| --- | --- | --- | --- |
| 현장코드 | 필수 | - | 조회할 현장 |
| start | 선택 | 7일 전 | 조회 시작 시점 |
| end | 선택 | 현재 | 조회 종료 시점 |

### 처리 절차

1. 지정한 현장과 기간의 알람 기록을 읽는다.
2. 같은 시각·센서·채널의 기록을 한 건으로 묶는다.
3. 최근 발생 순으로 정렬해 내보낸다.

### 예외 처리

- 현장 코드가 없으면 요청을 거부한다.
- 해당 기간에 알람이 없으면 빈 목록을 내보낸다.

## 1.11 문자 발송

### 기능 설명

문자 발송 서비스와의 **연동이 정상인지 확인**하는 기능이다. 정해진 번호로 시험 문자를 한 건 발송한다.

실제 알람 문자는 수집 서버가 알람을 판정한 뒤 발송한다. 이 기능은 발송 경로 점검용이다.

### 요청 형식

```text
GET /api/aligo/send
```

### 예외 처리

- 문자 발송 서비스 인증 정보가 설정되어 있지 않으면 기능을 사용할 수 없다고 응답한다.

## 1.12 자동 백업

### 기능 설명

지정된 센서의 측정 데이터를 **외부 백업 서버로 보내고, 백업이 끝난 데이터를 실시간 저장소에서 정리**한다. 실시간 저장소가 계속 커지지 않도록 하는 것이 목적이다.

서버가 시작되면 자동으로 예약되어 매일 정해진 시각에 한 번 실행된다. 관리자가 직접 실행할 수 있는 기능도 함께 제공한다.

### 처리 절차

1. 대상 센서의 지난 데이터 구간을 정한다.
2. 해당 구간을 외부 백업 서버로 전송한다.
3. 백업이 성공하면 실시간 저장소에서 그 구간을 정리한다.
4. 백업이 실패하면 정리하지 않는다.

### 요청 형식

```text
GET /api/backup/sensor-backup
```

### 예외 처리

- 외부 백업 서버가 응답하지 않으면 데이터 정리를 건너뛴다. 따라서 백업되지 않은 데이터가 삭제되는 일은 없다.
- 현재 백업 대상 센서는 설정에 지정된 일부 센서로 한정된다.

## 1.13 공통 등록·수정·삭제 규칙

### 기능 설명

관리 서버의 기준 정보 관리 기능은 **대상만 다르고 동작 방식이 동일**하다. 이 절의 규칙이 아래 대상 전체에 공통으로 적용된다.

### 표시 규칙

| 동작 | 요청 방식 | 설명 |
| --- | --- | --- |
| 목록 조회 | `GET` | 조건에 맞는 항목 전체와 개수를 함께 내보낸다 |
| 단건 조회 | `GET` + 식별자 | 항목 하나를 내보낸다 |
| 등록 | `POST` | 새 항목을 만들고 만들어진 내용을 함께 내보낸다 |
| 전체 수정 | `PUT` | 항목 내용을 지정한 값으로 바꾼다 |
| 부분 수정 | `PATCH` | 지정한 항목만 바꾼다 |
| 삭제 | `DELETE` | 항목을 지운다 |

응답은 성공 여부와 결과를 함께 담는다. 목록 조회에는 항목 개수가 포함되며, 조회 결과가 없으면 오류가 아니라 빈 목록을 내보낸다.

### 대상별 차이

| 대상 | 식별 방법 | 목록 조회 조건 | 특이사항 |
| --- | --- | --- | --- |
| 사용자 | 아이디 | 소속 현장·역할·상태 | 부분 수정 방식 사용 |
| 현장 | 번호 또는 현장 코드 | 없음 | 삭제 시 하위 전부 삭제 |
| 계층 | 번호 | 현장 또는 상위 계층 | 하위가 있으면 삭제 제한 |
| 폴더 | 번호 | 계층 또는 현장 코드 | 계층 하나에 소속 |
| 장비 | 번호 | 계층 또는 현장 코드 | 채널 변경 기능 별도 |
| 장비 종류 | 번호 | 사용 여부 | 장비 등록 시 선택 목록 |
| 센서 종류 | 번호 | 사용 여부 | 장비 등록 시 선택 목록 |
| 센서 그룹 | 번호 | 현장 번호 또는 현장 코드 | 표시 여부·순서 변경 별도 |
| 위젯 | 번호 | 현장 코드 | 표시 여부·순서 변경 별도 |
| CCTV | 번호 | 현장 코드 | 순서 변경 별도 |

### 예외 처리

- 필수 항목이 빠지면 무엇이 빠졌는지 함께 안내한다.
- 식별자 형식이 맞지 않으면 요청을 거부한다.
- 대상이 존재하지 않으면 찾을 수 없다고 응답한다.
- 다른 항목이 참조하는 대상은 삭제가 제한될 수 있다.

## 1.14 기능별 특성 요약

| 기능 | 보관 위치 | 다른 서버 영향 |
| --- | --- | --- |
| 로그인·사용자 관리 | PostgreSQL, Redis | 없음 |
| 현장·계층·장비 관리 | PostgreSQL | 화면 구성과 수집 대상에 반영 |
| 화면 구성 | PostgreSQL | 대시보드 표시에 반영 |
| 임계값 설정 | PostgreSQL | **수집 서버의 알람 판정 기준 변경** |
| 알람 이력 조회 | InfluxDB | 없음 |
| 문자 발송 | 외부 서비스 | 없음 |
| 자동 백업 | Redis, 외부 백업 서버 | **실시간 데이터 정리** |

대부분의 기능은 기준 정보를 바꾸는 데 그치지만, **임계값 설정은 알람 동작을 바꾸고 자동 백업은 실시간 데이터를 정리**한다. 운영 중 주의가 필요한 기능은 이 두 가지다.

현장 삭제는 하위 구성 전체가 함께 지워지므로 별도의 확인 절차를 두는 것이 바람직하다.
