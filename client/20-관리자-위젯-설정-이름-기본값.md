# 관리자·위젯 설정 이름 기본값 — 프로그램 명세

**작성 기준**: `DeviceManagerMetaForm.jsx`, `useWidgetManagerGroups.js`, `WidgetSettingDrawer.jsx`

**구분**: 이 문서는 **사용자에게 보이는 이름**(디바이스·노드·폴더·위젯·컬럼명)의 자동 기본값과 저장·재로드 규칙이다. 코드 식별자(파일명·컴포넌트명·SWR 키) 기준은 [16-관리자-설정-네이밍-기준.md](./16-관리자-설정-네이밍-기준.md)를 본다.

---

## 1. 데이터 구조와 흐름

### 1.1 핵심 원칙

1. **저장된 값은 그대로 신뢰한다.** 다시 열 때 이름 문자열(`축 1`, `val01`, `센서명` 등)과 비교해 "기본값인지" 추측하지 않는다. 사용자가 우연히 같은 문자열을 넣으면 덮어써지는 문제가 생긴다.
2. **자동/수동 구분은 구조적 사실로 판단한다.** 예: `options.sensorList`에 해당 채널 row·item이 **이미 저장돼 있는지**(`hasStoredItems`).
3. **추가 폼은 부모 레코드의 이름·설명을 상속하지 않는다.** 현장 식별자(`siteCode`)처럼 상속이 의미 있는 필드만 예외.
4. **기본값 축은 잘 바뀌지 않는 값에서 만든다.** 컬럼명은 데이터키(`dataIndex`). LoRa는 데이터키가 `val01` 형태라 센서명을 쓴다.
5. **기존 DB 데이터는 마이그레이션하지 않는다.** 정책 변경 이전에 저장된 컬럼명·위젯명은 그대로 둔다.

### 1.2 대상별 기본값 (확정, 2026-07-27)

| 대상 | 기본값 | 저장 | 순번 범위 | 비고 |
|------|--------|------|-----------|------|
| 디바이스 이름 | 종류 라벨 + 순번 (`지중경사계1`) | 저장 | 부모 아래 디바이스 수 | 종류 select 변경 시 채움 |
| 노드 이름 | `노드 1` | 저장 | 부모 아래 구조 노드 수 | |
| 폴더 이름 | `폴더 1` | 저장 | 부모 아래 폴더 수 | |
| 설명 | 빈 값 | — | — | 부모 description 상속 안 함 |
| siteCode | 부모 값 | — | — | 현장 식별자, 상속 유지 |
| 채널명·채널 그룹명 | 현행 (`변위계1`, `그룹명-01`) | 현행 | — | 하위 화면 소스, **변경 없음** |
| 위젯명 | 센서 타입 라벨만 (`변위계`) | 저장 | 순번 없음 | 빈 그룹 + `그룹 N`일 때만 자동 재명명 |
| 컬럼명 | 데이터키(`dataIndex`) | 저장 | — | LoRa만 센서명 |

### 1.3 디바이스 관리자 — 추가 폼

**진입**

`TreeNode.jsx`의 추가 버튼이 `mode: 'add'`와 **부모 노드**를 `data`로 넘긴다. 폼의 `data`는 새로 만들 레코드가 아니라 부모다.

**초기값**

- `mode === 'add'`일 때 `data?.name` / `description` / `deviceId`를 상속하지 않는다.
- 노드·폴더: 폼 오픈 시 `buildAddModeName(type, parent)` → `노드 N` / `폴더 N`.
- 디바이스: 이름은 종류 라벨이 필요해서 **빈 값**으로 두고, 종류 select `onChange`에서 `지중경사계1` 형태로 채운다.
- `siteCode`는 노드 추가 시 부모(또는 상위) 값을 그대로 둔다.

**순번**

`nextChildSequence(parent, childType)` — 부모 `children` 배열에서 같은 `type`(`device` / `folder` / 구조 노드) 개수 + 1.

**사용자 입력 보호**

종류를 바꿀 때 자동으로 채운 이름만 덮어쓴다. `autoFilledDeviceNameRef`에 마지막 자동값을 두고, 현재 이름이 그 값과 다르면 사용자가 직접 수정한 것으로 보고 유지한다.

**예외**

최상위 프로젝트 노드 생성(`data == null`)은 형제 목록이 없어 이름 기본값을 넣지 않는다(빈 값, 사용자 입력 필수).

### 1.4 위젯 관리자 — 위젯명

**자동 재명명 조건**

빈 그룹(`sensorIds.length === 0`)에 센서를 **처음** 넣을 때, 그룹 이름이 `그룹 N` 패턴(`isDefaultGroupName`)이면 센서 타입 라벨로 바꾼다.

**형식**

`buildSensorTypeGroupName(sensorType, sensorTypeNameMap)` → catalog 이름 또는 siteConfig 라벨 또는 code. **순번·`위젯 N` 접두사 없음.**

같은 타입 위젯이 여러 개면 목록·기준치 화면에서 동일 이름으로 보일 수 있다(의도된 선택, 2026-07-27).

**CCTV**

`CCTV 그룹 N` 등 CCTV 전용 이름 규칙은 이 문서 범위 밖이며, `useWidgetManagerGroups.js`의 CCTV 경로를 유지한다.

### 1.5 위젯 설정 — 컬럼명

**해석 순서**

`resolveItemColumnName(item)` → `item.columnName`.trim() || `item.name`.trim().

**신규·미저장 항목**

`buildSettingSensorList` → `applySensorItemNames(items, parseType, sensorName, hasStoredItems)`.

- `hasStoredItems === true`이고 `resolveItemColumnName(item)`이 있으면 **저장값 그대로**.
- 없으면 `buildDefaultColumnName`:
  - LoRa: `sensorName`
  - 그 외: `dataIndex` → 없으면 `sensorName` → `값 ${index + 1}`

**제거된 패턴 (2026-07-27)**

- `buildSensorItemName(deviceId, sensorName)` → `deviceId-센서명` 자동값 **제거**
- `isGeneratedItemName` → 이름 문자열 추측 **제거**

**geocus**

템플릿에서 아이템 생성 시 fallback 순서는 **데이터키 → 센서명**(`buildGeocusItemFromTemplate`).

### 1.6 채널명 (현행 유지, 예외)

채널명·그룹명은 위젯 관리자 좌측 센서 표시명·컬럼명 fallback의 **상위 소스**다. 2026-07-27 정책에서 **변경하지 않았다.**

- 저장 시 빈 이름이면 `buildAutoName(sensorType, socket)` (`변위계1` 등)
- 그룹: `buildGroupedChannelName(groupName, groupIndex)` (`그룹명-01`)

### 1.7 기존 데이터

- 이미 저장된 `deviceId-센서명` 형식 컬럼명: **마이그레이션 없음**, 그대로 표시·저장.
- 신규 생성·미저장 item부터 데이터키 기본값 적용.

## 4. 구현 시 주의사항

1. 저장값과 기본값 문자열을 비교해 덮어쓰지 않는다. 사용자 입력이 사라지는 회귀의 원인이다.
2. CCTV 그룹명 규칙은 본 문서 범위 밖이다.
3. 최상위 프로젝트 노드는 이름 기본값이 없다(빈 값).
4. 기존 DB에 저장된 이름은 마이그레이션하지 않는다.

---

## 5. 검증 기준

- **디바이스 관리자**: 노드·폴더·디바이스 추가 시 이름 칸에 부모명이 아닌 기본값이 들어간다. 디바이스는 종류 선택 후 이름이 채워진다.
- **위젯 관리자**: 빈 `그룹 N`에 센서 첫 투입 시 위젯명이 `변위계` 등 라벨만 된다.
- **위젯 설정**: 신규 센서 item 컬럼명이 데이터키(LoRa는 센서명)로 저장된다. 저장 후 재오픈·saveAll 시 컬럼명이 덮어써지지 않는다.
- **기존 위젯**: 이전에 저장한 컬럼명이 그대로 유지된다.

---

## 6. 확인 필요 사항

- 최상위 노드 생성 시에도 `노드 1` 기본값을 넣을지.
- 위젯명 라벨만 정책으로 목록 구분이 불편해지면 순번 재도입 여부.
