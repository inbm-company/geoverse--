# 관리자 설정 네이밍 기준 — 프로그램 명세

**구분**: 코드 식별자 네이밍 기준. 런타임 표시 이름은 [20-관리자-위젯-설정-이름-기본값.md](./20-관리자-위젯-설정-이름-기본값.md)를 본다.

---

## 1. 데이터 구조와 흐름

### 1.1 네이밍 원칙

1. UI 표현을 최상위 이름으로 (`DeviceManager`, `WidgetManager`)
2. 하위: `{Domain}Drawer`, `{Domain}Panel`, `use{Domain}*`, `{domain}Utils`
3. 센서 데이터 필드(`sensorId`, `sensorType`)와 UI 도메인명 구분
4. SWR/API payload 키 변경 시 읽기·쓰기 동시 수정

### 1.2 UI ↔ SWR ↔ 코드 매핑

| UI 표현 | SWR `drawer-opened` | 기준 이름 |
|---------|---------------------|-----------|
| 디바이스 관리자 | `device-manager` | `DeviceManager` |
| 디바이스목록 | `device-type-manager` | `DeviceTypeManager` |
| 센서목록 | `sensor-type-manager` | `SensorTypeManager` |
| 위젯 관리자 | `widget-manager` | `WidgetManager` |
| 위젯 설정 | `widget-manager` + `widget-setting-drawer-target` | `WidgetSetting` |
| 기준치설정 | `threshold-setting` | `ThresholdSetting` |
| 알림로그 | `log` | `AlarmLog` |
| 서버 상태 | `sys-monitor` | `ServerStatus` |
| 현장 모니터링 | `site-monitoring` | `SiteMonitoring` |

## 3. 사용 컴포넌트 설명

각 Drawer/Wrapper는 UI 도메인명과 1:1 대응. Header 메뉴 라벨과 SWR 키가 위 표와 일치해야 한다.

---

## 4. 구현 시 주의사항

1. 새 관리 드로어 추가 시 `{UiDomain}Drawer` + `drawer-opened` 문자열 등록.
2. DB/API 필드명은 UI 리네임만으로 변경하지 않음.
3. `MANAGER_DRAWER_WIDTH` 공통 상수 사용.
