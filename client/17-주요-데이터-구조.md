# 주요 데이터 구조 — 프로그램 명세

**작성 기준**: `services/*.js`, `config/siteConfig.js`, 실제 API 응답

이 문서는 시스템 전역에서 공유하는 SWR 키, JSON 스키마, API 엔드포인트의 정본이다.

---

## 1. 데이터 구조와 흐름

### 1.1 SWR 키 (디테일 드로어)

SWR을 fetcher 없이 전역 상태 저장소로 사용한다. `mutate(key, value)`로 쓰고 `useSWR(key)`로 읽는다.

| SWR key | 값 예시 | 용도 | 렌더 위치 |
|---------|---------|------|-----------|
| `drawer-opened` | `'chart-detail'`, `'widget-detail'`, `null` | 현재 열린 드로어 타입 | 공통 |
| `chart-detail-params` | `{ sensorType, chartId, sensorId, channel, mode }` | Bento/siteConfig 차트 상세 파라미터 | `DashboardDrawerManager` → `ChartDetailDrawer` |
| `widget-detail-widget` | DB 위젯 객체 | 위젯 그리드 상세 대상 | `WidgetGridLayoutDashboard` → `WidgetDetailDrawer` |
| `widget-detail-scope` | `{ sensorId, channel }` 또는 `null` | 형제 위젯 채널 필터 | `WidgetGridLayoutDashboard` → `WidgetDetailDrawer` |

### 1.2 SWR 키 (관리자·전역)

| SWR key | 용도 |
|---------|------|
| `widget-setting-drawer-target` | 위젯 설정 드로어 대상 |
| `site-thresholds` | 현장 기준치 캐시 |
| `sensor-data` | 소켓 차트 데이터 |
| `gauge-sensor-data` | 소켓 게이지 데이터(채널 병합) |
| `websocket-connection-status` | `Connecting` / `Connected` / `Disconnected` |
| `blueprint-opened` | 조감도 오픈 상태 |
| `groups-${siteCode}` | DB 센서 그룹 |
| `project-${siteCode}` | DB 프로젝트(마커 등) |
| `catalog-sensor-types` | 센서 타입 카탈로그 |
| `['sensor-types', 'list', 'active']` | 활성 센서 타입 |
| `['cctv-cameras', siteCode]` | CCTV 카메라 목록 |
| `['geoeco-folders', siteCode]` | GeoEco 구간 탭 |
| `['devices-subtree', siteCode]` | `deviceId → folderId` 매핑 |
| `['sensor-widgets', siteCode, 'geoeco']` | GeoEco 위젯 목록 |

**핵심 필드**

| 필드 | 설명 |
|------|------|
| `widgetType` | `widget` / `sensor-widget` / `folder`(레거시) / `cctv` |
| `showHide` | 대시보드 노출 여부 |
| `orderIndex` | 정렬 순서 |
| `options.parseType` | 계산기 선택 (`gdms` / `lora` / `geocus` / `fft`) |
| `options.sensorType` | 센서 타입 코드 |
| `options.values[]` | 값(축) 정의 — 라벨 + dataIndex |
| `options.sensorList[]` | 채널별 센서·계산식 |
| `options.deviceChannels[]` | 디바이스·채널 페어 |
| `options.chartType[]` | 렌더 컴포넌트 목록 |
| `is_sibling` | 형제 위젯 여부(scope 필터 대상) |

### 1.4 센서 타입 데이터 구조

```json
{
  "id": 1,
  "code": "windSpeed",
  "name": "풍속",
  "defaultOptions": {
    "values": [
      {
        "key": "ws",
        "formulaExample": ""
      }
    ],
    "parseType": "geocus",
    "formulaExample": ""
  },
  "meta": {},
  "isActive": true,
  "createdAt": "2026-04-20T23:28:08.469Z",
  "updatedAt": "2026-06-09T00:13:52.485Z"
}
```

`defaultOptions`는 빈 그룹에 첫 센서가 배정될 때 위젯 `options`로 1회 복사된다. 이후 위젯 options는 카탈로그와 독립적으로 관리된다.

## 2. 관련 파일과 주요 함수

### 2.1 서비스 계층

| 파일 | 역할 | 주요 메서드 |
|------|------|-------------|
| `src/services/sensorWidgetService.js` | 위젯 CRUD | `getSensorWidgets`, `create`, `update`, `reorder` |
| `src/services/sensorTypeService.js` | 센서 타입 카탈로그 | `list`, `create`, `update`, `remove` |
| `src/services/deviceService.js` | 디바이스 트리 | `getSubtree`, `createDevice`, `updateDevice` |
| `src/services/projectService.js` | 프로젝트·그룹 | `getGroupsBySiteCode`, `getProjectBySiteCode`, `updateProjectBlueprintChannelMarkers` |
| `src/services/thresholdService.js` | 기준치 | `fetchThresholds`, `saveThresholds` |
| `src/services/alarmLogService.js` | 알림 로그 | 기간·limit·offset 조회 |
| `src/services/cctvCameraService.js` | CCTV 카탈로그 | 아래 3.3 표 참조 |
| `src/services/folderService.js` | 폴더(디바이스 그룹) | `getFolders({ siteCode })`, `getFolders({ nodeId })` |
| `src/services/authTokenClient.js` | 토큰 저장·401 재발급 | `getAccessToken`, `setAuthTokens`, `clearAuthStorage` |

모든 서비스는 snake_case 응답을 camelCase로 정규화하고, HTTP status + 서버 메시지로 공통 실패 처리한다.

### 2.2 센서 데이터 API

| 엔드포인트 | 파라미터 |
|-----------|----------|
| `GET /api/sensors/realtime` | `sensorId`, `hours`, `aggregateSeconds`, `types`, `channel` |
| `GET /api/sensors/range` | `sensorId`, `start`, `end`, `types`, `channel`, `isFft`, `isLora` |

- `types`: `avg` 또는 `avg,min,max`
- `start` / `end`: ISO 8601 (UTC)
- `isLora`: `parseType`이 `lora` / `gdms`이거나 `sensorId`가 `lora_` 접두일 때 `true`

### 2.3 인증 API

| 엔드포인트 | 용도 |
|-----------|------|
| `POST /api/auth/login/v2` | 로그인 |
| `GET /api/auth/verify` | 세션 검증 (무효 토큰도 200 + `valid:false`) |
| `POST /api/auth/refresh` | accessToken 재발급 |
| `POST /api/auth/logout` | 로그아웃 |

Access Token 약 15분, Refresh Token 약 7일. localStorage 키는 `authToken`, `refreshToken`, `authUser`.

## 3. 사용 컴포넌트 설명

### 3.1 SWR 키 소비 위치

| SWR key | 쓰는 곳 | 읽는 곳 |
|---------|---------|---------|
| `drawer-opened` | `Header`, `Dashboard`, 차트 컴포넌트 | `App`, `DashboardDrawerManager`, `WidgetDetailDrawer` |
| `chart-detail-params` | `Dashboard`, `LowFrequencyChart`, `HighFrequencyChart`, `SensorValueBarChart`, `SensorStackedBarChart` | `ChartDetailDrawer` |
| `widget-detail-widget` / `widget-detail-scope` | `WidgetGridCardContent` | `WidgetDetailDrawer` |
| `gauge-sensor-data` | `SocketControl` | `useGaugeData`, `useWidgetGridCardData` |
| `sensor-data` | `SocketControl` | 고빈도 `RealtimeChart` |

### 3.2 폴더(디바이스 그룹) API

디바이스 매니저 노드 하위 1뎁스 그룹. GeoEco 구간 탭과 디바이스 매니저 트리에서 공통 사용한다.

`GET /api/folders?nodeId={nodeId}` 또는 `GET /api/folders?siteCode={siteCode}` — **둘 중 하나만** 지정한다.

| 파라미터 | 동작 |
|----------|------|
| `nodeId` | 해당 노드의 폴더 목록 |
| `siteCode` | 최상위 노드를 찾은 뒤 해당 노드 폴더 반환 |

응답 예시:

```json
{
  "success": true,
  "data": [
    {
      "id": 1,
      "nodeId": 15,
      "name": "가시설",
      "description": null,
      "orderIndex": 0
    }
  ],
  "count": 1,
  "nodeId": 15,
  "siteCode": "1000"
}
```

현장·노드가 없으면 `data: []`, `count: 0`, `nodeId: null`을 반환한다.

### 3.3 CCTV 카메라 API

현장별 CCTV 카탈로그. 위젯 관리자에서 CCTV 그룹에 배정하고, 대시보드 `CctvWidget`과 조감도 CCTV 마커에서 사용한다. base는 `BASE_URL.MANAGEMENT`.

| 메서드 | API | 용도 |
|--------|-----|------|
| `getCctvCameras(siteCode)` | `GET /api/cctv-cameras?siteCode=` | 목록 |
| `createCctvCamera(payload)` | `POST /api/cctv-cameras` | 등록 |
| `updateCctvCamera(id, payload)` | `PUT /api/cctv-cameras/{id}` | 수정 |
| `deleteCctvCamera(id)` | `DELETE /api/cctv-cameras/{id}` | 삭제 |
| `reorderCctvCameras(siteCode, orders)` | `PATCH /api/cctv-cameras/reorder` | 순서 변경 |

- 카메라 row: `id`, `siteCode`, `name`, `url`, `orderIndex`
- 삭제 시 위젯에 배정된 카메라면 HTTP 409 + `widgetIds[]` 반환
- CCTV 위젯 저장: `widgetType: 'cctv'`, `options.cameras[]`(`id`, `name`, `url`), `options.layoutMode`(`auto` / `single` / `grid` / `carousel`)

## 4. 구현 시 주의사항

1. SWR 키 문자열 변경은 세팅 위치와 읽는 위치를 같은 작업에서 함께 바꾼다.
2. snake_case → camelCase 정규화는 service 계층에서만 수행한다. 컴포넌트에서 원본 키를 직접 쓰지 않는다.
3. 위젯 `options` 스키마는 `parseType`별로 하위 필드가 다르다. 공통 필드만 가정하지 않는다.
4. API payload·DB 저장 필드는 UI 네이밍 정리만으로 바꾸지 않는다.
5. `/api/folders`와 `/api/devices/subtree`는 `nodeId`와 `siteCode`를 동시에 지정할 수 없다.
