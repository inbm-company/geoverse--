# 위젯 그리드 상세 드로어 — 프로그램 명세

**작성 기준**: `WidgetDetailDrawer.jsx`, `widgetDetailDrawerUtils.js`, `useWidgetDetailData.js`

---

## 1. 데이터 구조와 흐름

### 1.1 ChartDetailDrawer vs WidgetDetailDrawer

| 구분 | ChartDetailDrawer | WidgetDetailDrawer |
|------|-------------------|-------------------|
| SWR params | `chart-detail-params` | `widget-detail-widget`, `widget-detail-scope` |
| drawer-opened | `chart-detail` | `widget-detail` |
| 데이터 훅 | `useNormalData` / `useFftData` | `useWidgetDetailData` |
| 출처 | siteConfig | DB widget.options |
| 렌더 | DashboardDrawerManager | WidgetGridLayoutDashboard |
| 모바일 | Manager에서 닫음 | `!isMobile`만 open |

### 1.2 오픈/닫기

```javascript
// openWidgetDetailDrawer(widget, scope)
mutate('widget-detail-widget', widget)
mutate('widget-detail-scope', isSibling ? scope : null)
mutate('drawer-opened', 'widget-detail')

// closeWidgetDetailDrawer()
mutate('drawer-opened', null)
mutate('widget-detail-scope', null)
```

**제외 대상**: projectWidget, cctv, getProjectWidgetType() 존재, id 없음

### 1.3 scope 규칙

- `isSibling === true`만 `{ sensorId, channel }` 필터
- LoRa: channel `'lora'` 정규화
- scope 없으면 위젯 전체 채널

### 1.4 useWidgetDetailData

1. 차트 센서: `getWidgetLowFrequencyChartProps` + scope 필터
2. 테이블: `getWidgetDetailTableSensors` + scope 필터
3. range: `getSensorWidgetRangeRequests` → `rowsByChannel`
4. 가공: `buildWidgetDetailRangeData`, `buildWidgetDetailChartBundle`
5. `initialData`: 빈 객체 (위젯 경로는 초기치 구간 별도 없음)

### 1.5 패널 분기

| parseType | 패널 |
|-----------|------|
| `gdms` | `GdmsDrawerPanel` |
| `fft` | `FftDrawerPanel` + `useWidgetFftImageData` |
| 그 외 | `NormalDrawerPanel` |

## 2. GDMS 프로파일 차트

`GdmsDrawerPanel`은 프로파일 차트를 `GdmsProfileChart`로 렌더한다. `GdmsProfileChart`는 직접 그리지 않고 위젯 옵션의 `gdmsChartOption` 값으로 실제 차트를 고르는 디스패처다.

### 2.1 차트 옵션 3종

| `gdmsChartOption` | 라벨 | 컴포넌트 | 대상 계측기 |
|-------------------|------|----------|-------------|
| `vertical` | 수직 (지중경사계) | `GdmsVerticalProfileChart` | 지중경사계 |
| `horizontal` | 수평 (도상침하계) | `GdmsHorizontalProfileChart` | 도상침하계 |
| `semicircle` | 반원 (내공변위계) | `GdmsSemicircleProfileChart` | 내공변위계 |

상수와 라벨은 `gdmsWidgetCalculations.js`의 `GDMS_CHART_OPTIONS` / `GDMS_CHART_OPTION_LABELS`에 있다. `normalizeGdmsChartOption`이 값을 소문자 trim 후 판정하고, 미지정·미인식 값은 모두 `vertical`로 폴백한다. 위젯 설정에서 옵션을 고르는 UI는 [14-위젯-설정-드로어.md](./14-위젯-설정-드로어.md)를 본다.

### 2.2 두 갈래 모델

옵션 3종은 모델을 만드는 방식이 두 갈래로 나뉜다. 어느 쪽이든 축 정의·채널 순서·누적 계산은 `buildGdmsAxisTableModel`에서 나온다.

| 갈래 | 옵션 | 축과 패널의 관계 |
|------|------|------------------|
| 프로파일형 | `vertical`, `horizontal` | 축 하나가 패널 하나. 변위가 독립 축을 가진다 |
| 좌표형 | `semicircle` | 축 두 개를 X·Y로 묶어 패널 하나. 변위가 좌표에 더해진다 |

생성 함수는 `buildGdmsVerticalProfileChartModel`, `buildGdmsHorizontalProfileChartModel`, `buildGdmsSemicircleProfileChartModel`이다. `buildGdmsProfileChartModel`은 수직 모델의 구 이름이며 신규 코드에서 쓰지 않는다.

### 2.3 프로파일형 (수직·수평)

두 차트는 `buildProfileAxes` 하나를 공유하고 **좌표 매핑 콜백만** 다르다.

| 필드 | 의미 |
|------|------|
| `axes[].dataIndex` | 축 식별자 |
| `axes[].name` | 축 이름 (`values[]`의 라벨) |
| `axes[].channelCount` | 채널(깊이·지점) 개수 |
| `axes[].depthSpacing` | 채널 간격. 상수 `DEFAULT_DEPTH_SPACING = 2` |
| `axes[].accumulate` | 누적 여부 (`gdmsPointAccumulate`) |
| `axes[].series[]` | 시각별 프로파일. `series[0]`이 최신(`isLatest: true`) |
| `axes[].series[].points[]` | 좌표 배열 |

`channelIndex`는 0부터, `maxChannelIndex = channelCount - 1`, `spacing = 2`다.

| 옵션 | 좌표 | 축 구성 |
|------|------|---------|
| `vertical` | `[변위, -((maxChannelIndex - channelIndex) × spacing)]` | x = 변위(대칭), y = 심도(음수 ~ 0) |
| `horizontal` | `[channelIndex × spacing, 변위]` | x = 지점, y = 변위(대칭) |

변위 축은 0을 중심으로 대칭이며 범위는 `resolveAxisSymmetricDisplacementHalfRange(axis, widgetOptions, thresholdMap, displacementIndex)`가 계산한다.

1. `collectAxisDisplacementMaxAbs` — 해당 축 모든 프로파일 좌표에서 변위 절댓값의 최대치
2. `collectAxisThresholdLimits` — `sensorList[]`를 돌며 `${deviceId}::${channel}::${dataIndex}` 키로 기준치를 찾아 `limit1`·`limit2`·`limit3` 절댓값 수집
3. 두 값 중 큰 쪽을 `resolveSymmetricXHalfRange`에 넣어 `max(20, ceil((maxAbs + 10) / 10) × 10)` 으로 확정

최소 반범위 상수는 `GDMS_PROFILE_X_MIN_HALF_RANGE = 20`이다. `displacementIndex`는 좌표 배열에서 변위가 몇 번째인지를 가리키며, 수직은 `0`, 수평은 `1`이다.

심도는 음수로 표기한다. 축 라벨과 툴팁에 절댓값 변환을 넣지 않는다.

### 2.4 좌표형 (반원·내공변위계)

반원은 각도 배치가 아니다. **센서마다 실제 설치 좌표가 있고, 거기에 누적변위를 더한 XY 점을 시각별로 선으로 잇는다.** 터널 단면 변형 형상이 결과로 나온다.

| 요소 | 대응 |
|------|------|
| 축 2개 | 첫 번째 축 = X, 두 번째 축 = Y. 축 순서는 `sensorList[].items` 순서(폴백은 `options.values`)를 따른다 |
| 선 1개 | 측정 시각 1개. `series[0]`이 최신 |
| 점 1개 | 채널(센서) 1개 |

좌표 계산은 다음과 같다.

```
점(시각 t, 채널 c) = [initX(c) + dx(t, c), initY(c) + dy(t, c)]

dx = X축 누적변위, dy = Y축 누적변위
양 끝 채널(c = 0, c = 마지막)은 고정점이라 변위를 더하지 않고 초기 좌표를 그대로 쓴다
```

초기 좌표는 `resolveGdmsSemicircleInitialCoords(widgetOptions, channelCount)`가 채널별로 제공한다. `sensorList[]`의 `initX` / `initY`를 읽고, 값이 없으면 원점(`0, 0`)을 쓴다. 초기 좌표가 없는 위젯은 양 끝이 원점에 모이고 중간 채널만 변위 좌표를 갖는 형태로 그려진다.

`dx`와 `dy`는 두 축의 셀을 `time` 기준으로 짝지어 얻는다. 한쪽이라도 값이 없으면 그 점은 `null`이 되어 선에 공백이 생긴다. 고정점은 변위를 참조하지 않으므로 해당 시각에 측정값이 없어도 초기 좌표로 항상 그린다.

축이 2개 미만이면 모델이 `hasEnoughAxes: false`를 반환하고 차트는 "반원 차트는 X·Y 값 2개가 필요합니다."를 표시한다.

좌표 범위는 `resolveGdmsSemicircleExtent(series)`가 정한다. 전체 점의 min/max 중심을 잡고, x·y 스팬 중 **큰 쪽**에 10% 여백을 더한 값을 양축에 같이 적용해 1:1 스케일을 만든다. 단면 형상이 일그러지지 않게 하려는 것이다. 점이 없으면 `GDMS_SEMICIRCLE_MIN_SPAN = 1` 기준의 기본 범위를 쓴다. 프로파일형의 대칭 범위 계산은 쓰지 않는다.

### 2.5 렌더 규칙

공통 규칙이다.

| 항목 | 규칙 |
|------|------|
| 값 라벨 | `accumulate`면 `누적변위`, 아니면 `변위` |
| 최신 프로파일 | 선 굵기 2.5, 심볼 4, `z: 10` |
| 과거 프로파일 | `rgba(140, 140, 140, 0.35)`, 선 굵기 1, 심볼 2, `z: 1` |
| 선 형태 | `smooth: false`, `animation: false` |
| 단위 | `options.unit` → `options.measurementUnit` → `'mm'` |
| 소수 자리 | `resolveSensorDecimals({ decimals: options.decimals })` |
| 툴팁 | `trigger: 'item'` |
| 상태 표시 | `error` → 오류 박스, `loading` → `LoadingState`, 데이터 없음 → "표시할 데이터가 없습니다." |

옵션별로 다른 부분은 아래와 같다.

| 항목 | `vertical` | `horizontal` | `semicircle` |
|------|-----------|--------------|--------------|
| 패널 배치 | 축마다 1개, 2열 그리드 | 축마다 1개, 세로 스택 | 전체 1개 |
| 패널 비율 | 종횡비 `2 / 3` | 높이 `maxPanelHeight / 2` | 종횡비 `1 / 1` |
| 패널 제목 | `{축 이름} ({값 라벨})` | `{축 이름} ({값 라벨})` | `{X축} · {Y축} ({값 라벨})` |
| 최신 색상 | 축 순서대로 `#2F54EB` `#F5222D` `#52C41A` `#FA8C16` | 동일 | 단일 차트라 `#2F54EB` 고정 |
| 툴팁 내용 | 시각, 심도, 변위 | 시각, 지점, 변위 | 시각, 센서명(고정점 표기), X·Y 좌표, 변위 쌍 |

`maxPanelHeight` 기본값은 720px이다.

## 5. 구현 시 주의사항

1. `chart-detail`과 `widget-detail` SWR 혼동 금지.
2. 차트 legend vs 테이블 3단 헤더 규칙 상이.
3. `widget-detail-widget`은 닫을 때 명시 clear 안 함.
4. GDMS 차트 옵션을 추가할 때는 `GDMS_CHART_OPTIONS` 상수, `normalizeGdmsChartOption` 판정, `GdmsProfileChart` 매핑, 위젯 설정 select를 함께 등록한다.
5. 프로파일 좌표 매핑은 `gdmsProfileChartModel.js`에만 둔다. 렌더 컴포넌트에서 좌표를 다시 계산하지 않는다.
6. 반원은 `buildProfileAxes`를 쓰지 않고 `buildGdmsAxisTableModel`을 직접 호출한다. 축을 X·Y로 소비하므로 프로파일형과 좌표 규약이 다르다. 프로파일형 헬퍼를 반원에 재사용하지 않는다.
7. 반원의 축 순서가 X·Y를 결정한다. 위젯 설정에서 `items` 순서가 바뀌면 좌표축이 바뀐다.
8. 반원 초기 좌표(`initX` / `initY`)를 입력하는 UI는 없다. 값이 비면 원점으로 처리하되, 계산은 항상 초기 좌표 + 변위 형태를 유지한다.
