# 센서 타입 기본 옵션 — 프로그램 명세

**작성 기준**: `SensorTypeManagerDrawer.jsx`, `SensorTypeCatalogManagerPanel.jsx`, `sensorTypeService.js`

---

## 1. 데이터 구조와 흐름

### 1.1 책임 범위

**포함**: code, name, parseType, chartType, defaultOptions, thresholdTemplate  
**미포함**: 개별 위젯명, sensorList, 채널 초기값, 위젯 기준치

### 1.2 진입

- SWR `drawer-opened === 'sensor-type-manager'`
- Header **센서목록** (super_admin)
- 권한: `isSuperAdmin && token` → CUD

### 1.3 목록 SWR

- Key: `catalog-sensor-types`
- Fetcher: `sensorTypeService.list({})`
- open일 때만 조회

### 1.4 defaultOptions 구조 (parseType별)

| parseType | Fields 컴포넌트 |
|-----------|-----------------|
| gdms | `SensorTypeGdmsFields` |
| lora | `SensorTypeLoraFields` (usedCount, singleOutput) |
| fft | `SensorTypeFftFields` |
| geocus | `SensorTypeGeocusFields` |

### 1.5 위젯과의 관계

빈 그룹에 **첫 센서** 배정 시 defaultOptions 1회 seed → 이후 위젯 options 독립

---

## 2. 관련 파일과 주요 함수

| 파일 | 역할 |
|------|------|
| `SensorTypeManagerDrawer.jsx` | Drawer shell |
| `SensorTypeCatalogManagerPanel.jsx` | 목록·SWR |
| `SensorTypeEditDialog.jsx` | 생성/수정 |
| `SensorTypeDefaultFields.jsx` | 공통 필드 |
| `sensorTypeService.js` | CRUD API |

**Legacy 변환**: `formula` → `formulaExample`, `thresholdSetting` → `thresholdTemplate`

---

## 3. 사용 컴포넌트 설명

| 컴포넌트 | 설명 |
|----------|------|
| `SensorTypeManagerDrawer` | 센서 타입 카탈로그 관리 |
| `SensorTypeEditDialog` | 추가/수정 모달 |
| `WidgetManagerDrawer` | seed 시 defaultOptions 소비 |

---

## 4. 구현 시 주의사항

1. catalog 수정이 **기존** 위젯 options에 영향 주면 안 됨.
2. parseType 없는 타입은 위젯 로컬 생성 불가.
3. 조회는 모든 사용자, CUD는 super_admin만.
